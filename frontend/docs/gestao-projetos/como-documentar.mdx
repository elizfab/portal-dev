# Como documentar um projeto

O objetivo é manter o contexto pequeno e reaproveitável. Cada projeto deve ter **apenas um README principal** e, quando necessário, um ou dois arquivos complementares no próprio repositório. O `Portal Dev` centraliza o manual geral.

:::warning[Evite]
Não crie cópias de documentação em `.vscode/docs`, `docs/` dos projetos e no Docusaurus ao
mesmo tempo. Isso cria versões divergentes.
:::

## Estrutura mínima do README

Use a ordem abaixo no `README.md` de cada projeto:

```markdown
# Nome do projeto

> Linha única sobre o que faz.

## 1. Identidade do projeto

| Campo | Valor |
| --- | --- |
| slug | nome-do-projeto |
| Categoria | Frontend / Backend / DevOps |
| Tipo | pessoal / profissional / estudo |
| Demo | https://... |

## 2. Como executar

```bash
cd frontend
npm install
npm start
```

## 3. Stack

- Angular 22
- TypeScript
- SCSS

## 4. Decisões técnicas

- Por que X em vez de Y.

## 5. Checklist

- [x] Setup
- [ ] Deploy
- [ ] Portfólio
```

## Onde vivem os detalhes

| Tipo de informação | Local correto | Exemplo |
| --- | --- | --- |
| Stack, comandos e deploy | `README.md` do projeto | `01.carteira-saude/README.md` |
| Decisões técnicas longas | `docs/decisoes.md` ou seção no README | `mfe-elizabetefabri-portfolio/docs/` |
| Guia de uso/comandos pessoais | `Portal Dev` (Docusaurus) | `docs/gestao-projetos/` |
| Tracking de tarefas | GitHub Project ou issues | [Project 2](https://github.com/orgs/elizfab/projects/2) |
